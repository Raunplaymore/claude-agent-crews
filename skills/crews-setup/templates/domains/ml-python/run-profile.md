## 전제

- [ ] venv가 있고 패키지가 설치되어 있다 (측정값의 설치 타깃 참조)
- [ ] 대상 설정 파일을 정했다 — 기본값을 그대로 쓰는지, `CONFIG=`로 바꾸는지
- [ ] 필요한 원본 데이터가 로컬에 있다 (없으면 어느 단계가 내려받는지 확인)
- [ ] 자격증명이 필요한 단계라면 `.env`가 준비되어 있다 (설정 파일에 키를 적지 않는다)
- [ ] 연산 장치가 현재 머신에서 유효하다 (설정의 device 값)

## 검증 경로

`[실행 확인]` 라벨은 이 표의 관측으로만 성립한다. 표에 없는 방법으로 확인했으면 이 표를 갱신한다.

| 확인 대상 | 관측 방법 | 정상 신호 |
|---|---|---|
| 파이프라인 완주 | 측정값의 파이프라인 타깃 | 각 단계 산출물이 새로 생성됨 (타임스탬프 확인) |
| 데이터 준비 | 전처리 산출물의 이미지·라벨 수 | (프로젝트에서 채움) |
| 학습 | 학습 실행 기록 디렉토리 | (프로젝트에서 채움 — 어느 지표를 보는가) |
| held-out 성능 | 검증 타깃 | (프로젝트에서 채움 — 기준값) |
| 변환 모델 동등성 | 원본과 같은 입력으로 비교 | (프로젝트에서 채움 — 허용 오차/게이트) |
| 기기·서버 동작 | 이 레포에서 확인 불가 | `[미검증]` — 아래 "이 레포에서 확인 못 하는 것" |

**학습 로그의 지표는 이 표의 어떤 행도 채우지 못한다.** "학습이 돌았다"는 `[정적 확인]`이다.

## 이 레포에서 확인 못 하는 것

`[미검증]`으로 남기고, 사람이 어디서 무엇을 봐야 하는지 적는다.

- 실제 기기·추론 서버에서의 지연·정확도
- 다운스트림 소비자(추론 서버·클라이언트)가 새 클래스 계약을 따르는지
- (프로젝트에서 채움)

| 대상 | 방법 | 순서 |
|---|---|---|

| 클래스 목록·메타 | (프로젝트에서 채움) | 모델보다 먼저/나중? |

클래스 목록이 바뀌면 **모델과 소비자 설정을 함께** 올려야 한다. 순서가 없으면 "없음"이라고 명시한다 —
비워 두면 다음 세션이 다시 추측한다.

## 비가역 단계

되돌리려면 재실행·재수집이 필요한 것들. **실행 전 사용자 확인을 받는다.**

- 전처리 산출물 재생성 (이전 라벨 매핑이 사라진다)
- 같은 실행 이름으로 재학습 (이전 산출물 덮어쓰기)
- 데이터 디렉토리 정리·삭제 (원본 재수집 비용)
- 원격 저장소·데이터셋 플랫폼에 업로드
- 소비자가 참조 중인 산출물 교체
