## 전제

- [ ] 보드가 USB로 연결되어 있고 포트가 보인다 (`pio device list`)
- [ ] 설정 헤더가 존재한다 (예시 헤더에서 복사 후 값 채움) — 위 측정값의 "설정 쌍" 참조
- [ ] (해당 시) Wi-Fi·서버 주소가 현재 네트워크에 맞다
- [ ] (해당 시) 동반 프로세스(게이트웨이 등)가 떠 있다

## 검증 경로

`[실행 확인]` 라벨은 이 표의 관측으로만 성립한다. 표에 없는 방법으로 확인했으면 이 표를 갱신한다.

| 확인 대상 | 관측 방법 | 정상 신호 |
|---|---|---|
| 부팅 | 시리얼 모니터 (측정값의 monitor_speed) | 부팅 로그 + 초기 진단 라인 |
| 메모리 | 부팅 로그의 힙/PSRAM 값 | (프로젝트에서 채움) |
| 센서·주변장치 초기화 | 시리얼 로그 | (프로젝트에서 채움) |
| 네트워크 | 시리얼 로그의 연결/재연결 | (프로젝트에서 채움) |
| 종단 동작 | (프로젝트에서 채움 — URL·화면·수신 로그) | (프로젝트에서 채움) |

**호스트 빌드는 이 표의 어떤 행도 채우지 못한다.** 빌드 성공은 `[정적 확인]`이다.

## 배포 / 반영 순서

| 대상 | 방법 | 순서 |
|---|---|---|
| 펌웨어 | `pio run -e {env} -t upload` | (프로젝트에서 채움) |
| 동반 프로세스 | (프로젝트에서 채움) | (프로젝트에서 채움) |
| 설정/시크릿 | 로컬 헤더·env 파일 갱신 (커밋 금지) | 펌웨어보다 먼저 |

여러 env가 있으면 **어떤 순서로 올려야 하는지**를 여기 적는다 (예: 수신측 먼저, 송신측 나중).
순서가 없으면 "없음"이라고 명시한다 — 비워 두면 다음 세션이 다시 추측한다.

## 비가역 단계

되돌리려면 물리적 개입이나 재설정이 필요한 것들. **실행 전 사용자 확인을 받는다.**

- 펌웨어 flash — 되돌리려면 이전 펌웨어를 다시 빌드해 올려야 한다
- NVS/EEPROM/파일시스템 초기화, 파티션 테이블 변경
- 부트로더·OTA 파티션 관련 변경 (실패 시 물리 접근 필요)
- 실기기·원격 호스트에서의 삭제·재기동
